# Test Specification — 04_blobstore

Tier: component integration (`cargo test -p blobstore`) at the public port boundary: `BlobWriter`, `BlobReader`, `BlobRegistry`, `BlobCatalog`, `GcQueue`, `Janitor` (`GcSweeper`, `OrphanSweeper`, `ScrubJanitor`), `Scrubber`, `BlobInventory`, `MasterKeyring`, `EpochMarker`, `BlobHealth`, `DoctorCheck`. Env class `C`; timing rows `C-REF`; filesystem-fault rows need a loop-mounted XFS image (`tests/tools/make-blob-volume.sh`). System scenarios are referenced by ID, not restated.

Real PostgreSQL 18 holds `blobs` and `blob_gc` (the component's tables). `BlobOwnerCleanup` is a recording test implementation here (the real one is 02's, exercised in 02 IT-02-23 and the integration suite). Fault injection uses decorators on the ports and direct file manipulation of the temp blob root (flip a byte, truncate, delete, `chmod`), the same operations `e2e-ctl` does at system level. Clock is the manual test clock; retention, intervals and leases are millisecond config values.

## Blackbox Tests

### IT-04-1: Write and read round trip, file layout, no plaintext
**Summary**: blobs written block by block (any order) read back byte-exact; the file holds only ciphertext in the specified layout.
**Traces to**: AC-43
**Description**: sizes 0, 1, 65,535, 65,536, 65,537, 2 MiB, 5 MiB+7 (generated by seeded ChaCha20; DS-09 marker every 1 MiB). `plan` -> `create_file(preallocate = true)` -> `write_block` in shuffled order from 4 tasks -> `await_durable` each -> `register_in_tx` + `mark_committed_in_tx` -> `open(None)`.
**Expected result**:
```
Read bytes == source for every size; BLAKE3 equal
file length = 64 + n_chunks * 16 + size; chunk i at 64 + i * (65536 + 16); header magic and format version present
grep for the 64-byte marker "SUNNYCLOUD-MARKER-<seed>" over the whole file and header: 0 hits
two blobs with identical plaintext have different ciphertext and different wrapped_key
```
**Max execution time**: 20 s; **Dependencies**: PostgreSQL, temp blob root

### IT-04-2: Nonce construction known-answer vectors
**Summary**: the hand-built STREAM nonce equals `aead-stream =0.6.0` byte for byte.
**Traces to**: AC-43
**Input data**: chunk positions 0, 1, n-1 (final flag), single-chunk file, empty file, counter 2^32-1 -> refusal; fixed prefix, key and AAD = blob_id.
**Expected result**: each vector sealed by the component equals the `aead-stream` output; counter limit returns a typed error, never wraps; AAD change makes `open` fail.
**Max execution time**: 5 s; **Dependencies**: none (pure); dev-dependency `aead-stream =0.6.0` as oracle

### IT-04-3: Random-access ranges
**Summary**: every range maps to the right chunks; a 4 KiB range reads at most 2 chunks.
**Traces to**: AC-43
**Input data**: 3 MiB blob; ranges: first byte, last byte, 4096 at offset 0 / 65,534 / 1,000,003, spanning 3 chunks, whole file, `start == size`, `end > size`, inverted.
**Expected result**: bytes equal the source slice; `pread` calls recorded by the file-handle decorator: <= 2 chunk reads (2 x 65,552 bytes) for each 4 KiB range; out-of-bounds -> `RangeNotSatisfiable`; `read_head(64 KiB)` returns the first 64 KiB, larger `max_bytes` rejected.
**Max execution time**: 8 s; **Dependencies**: PostgreSQL

### IT-04-4: Tampered or damaged files are never served as plaintext
**Summary**: any change to the file yields `Corrupt`, never bytes.
**Traces to**: AC-7, AC-43
**Input data**: (a) flip one bit in chunk k; (b) truncate to a chunk boundary; (c) truncate mid-chunk; (d) append 16 bytes; (e) swap two chunks within the blob; (f) copy a chunk from blob B2; (g) change the header nonce prefix; (h) drop the final-flag chunk.
**Expected result**:
```
Range avoiding the damaged chunk: bytes correct. Range or full read touching it: first chunk verified before open returns; later chunk -> stream yields Err(Corrupt) and ends; collected body is NEVER a complete-looking short body (consumer sees the error)
(b)(c)(d)(h): Corrupt on full read; (e)(f)(g): Corrupt on first touched chunk
blobs.unavailable_at set after the first Corrupt (one audit scrub_mismatch per blob per process run)
```
**Max execution time**: 10 s; **Dependencies**: PostgreSQL

### IT-04-5: Group-commit durability barrier
**Summary**: `await_durable` completes only after the covering `fdatasync`; failures reach every waiter; syncs are coalesced.
**Traces to**: AC-38
**Description**: sync function wrapped by the barrier's test hook: (a) block `fdatasync` for 300 ms; (b) make it fail; (c) 100 concurrent `write_block` + `await_durable` over 10 files.
**Expected result**:
```
(a) every await_durable pending >= 300 ms, none earlier; (b) all waiters in the group get Io; none gets a token that looks durable; later writes succeed after the fault clears
(c) all 100 durable; metric block_fsync_duration_seconds count (= number of group flushes) <= 25 and every file synced after its last write; single uncontended write acked in <= 20 ms (no artificial 1 s wait)
directory entry fsynced once at create_file (hook counter == 1 per file)
```
**Max execution time**: 15 s; **Dependencies**: PostgreSQL, XFS loop volume for (c) timing

### IT-04-6: write_complete and discard
**Summary**: small and derived blobs are synced before any row exists; failures leave no row.
**Traces to**: AC-68
**Input data**: 0 B, 1 B, 3 MiB stream; stream shorter/longer than `size`; stream error mid-way; volume with no space; floor not met; `discard` of an existing and a missing id.
**Expected result**: `WrittenBlob{plan, size}` with file readable only after the caller registers the row; no `blobs` row created by `write_complete`; `SizeMismatch`, `Io`, `NoSpace`, `FreeSpaceFloor` map correctly and leave no partial file; `discard` unlinks, missing id is `Ok`.
**Max execution time**: 10 s; **Dependencies**: PostgreSQL, small loop volume (64 MiB)

### IT-04-7: Free-space floor and preallocation
**Summary**: `create_file` refuses below the floor; preallocation prevents `ENOSPC` during an upload.
**Traces to**: AC-39
**Description**: 64 MiB loop volume, `blob_free_reserve = 8 MiB`; create 20 MiB blob with `preallocate = true`, then fill the rest of the volume with a filler file and write all blocks; a 60 MiB request; `BlobHealth::probe`.
**Expected result**: 60 MiB -> `FreeSpaceFloor` (no file); preallocated blob: every `write_block` succeeds although the filler used all other space; probe reports `below_floor = true` and `free_bytes` within 1 MiB of `statvfs`.
**Max execution time**: 10 s; **Dependencies**: loop volume (needs root, `C` with privileged runner)

### IT-04-8: Registry, catalog and reinstate
**Summary**: row transitions and account-scoped reads.
**Traces to**: AC-30, AC-65
**Expected result**:
```
register_in_tx(uploading) -> mark_committed_in_tx -> state committed; rollback of the caller tx removes the row
BlobCatalog::get_ref(account, blob) -> BlobRef{blob_id, size, wrapped_key, master_key_id}; other account's blob -> None; unknown -> None
reinstate_in_tx: blob in gc_pending within retention -> Reinstated (blob_gc row cleared, state committed); after retention and swept -> BeyondRetention; row present, file absent -> FileMissing; remove_row_in_tx deletes blobs + blob_gc rows
```
**Max execution time**: 6 s; **Dependencies**: PostgreSQL

### IT-04-9: GcQueue single writer
**Summary**: `schedule_in_tx` sets `blob_gc` and `gc_pending` together or not at all.
**Traces to**: AC-30, AC-27
**Input data**: `Due::AfterRetention` with `retention = 7 d` and with `0`; `Due::Now`; caller rollback; duplicate schedule of the same blob.
**Expected result**: `due_at = clock.now + retention` (7 d), `= now` for `Now`; rollback undoes both writes; duplicate schedule is idempotent (one row, earliest due kept); `pending_for_account` counts exactly queued, unremoved blobs of that account.
**Max execution time**: 4 s; **Dependencies**: PostgreSQL

### IT-04-10: GcSweeper cycle
**Summary**: nothing is removed early; backlog drains within one cycle; crashes are healed by the lease.
**Traces to**: AC-30, AC-27
**Description**: `gc_batch = 10`, `gc_claim_lease = 500 ms`, `gc_cycle_budget = 5 s`; 250 blobs due, 20 due in the future; one file already missing; recording `BlobOwnerCleanup`; kill the sweeper between unlink and the cleanup transaction for one batch (decorator error), then rerun after the lease.
**Expected result**:
```
Clock before due_at: 0 removed (retention - 1 ms). After due: one run_cycle removes all 250 due (25 batches), GcStats{removed 250, remaining_due 0, budget_spent false}; the 20 future ones stay
missing file: logged WARN, not an error, row still removed; cleanup called once per blob before remove_row_in_tx
interrupted batch: rows stay claimable after lease expiry (due_at moved forward), second cycle completes; no blob row left whose file exists, no file left whose row was removed
no DB transaction open across unlink (pg_stat_activity idle-in-transaction count 0 during the unlink hook)
```
**Max execution time**: 30 s; **Dependencies**: PostgreSQL

### IT-04-11: Scrub runs
**Summary**: `Full` and `Due` runs terminate under live traffic, report real corruption, are rate-capped and pause under load.
**Traces to**: AC-24, AC-7
**Description**: 300 committed blobs (1 MiB), 3 with a flipped bit, 2 with the file deleted; concurrent writer commits a new blob every 20 ms during the run; `rate = 10 MiB/s`; second run with the activity gauge above `scrub_pause_active_streams`.
**Expected result**:
```
start_run records started_at; run covers only blobs with created_at <= started_at; run_step loop reaches done = true (bounded by 300 + steps) although writers keep adding blobs; those belong to the next run
mismatched = 3, missing = 2; each gets unavailable_at and one scrub_mismatch audit event; finish_run writes one scrub_summary (integer counts, duration); status shows oldest last_scrubbed_at, unscrubbed count, unavailable count 5
measured read rate <= 11 MiB/s (+10%); Due mode skips blobs scrubbed within scrub_interval; with gauge above threshold run_step pauses (no ciphertext read while paused), resumes when it drops
```
**Max execution time**: 60 s; **Dependencies**: PostgreSQL

### IT-04-12: Scrub never reports a blob being uploaded or removed
**Summary**: false positives are excluded by construction (state filter, re-check, GC claim).
**Traces to**: AC-80
**Description**: (a) blob in `uploading` with half the blocks written (unwritten extents are zeros); (b) committed blob, scrub step paused after reading ciphertext (decorator), GC claims it, unlinks it, state `gc_pending`, then the step resumes; (c) 200 randomised-timing iterations of (b) with real concurrency; (d) control: real corruption on a committed blob.
**Expected result**:
```
(a) never selected: mismatched 0, no unavailable_at, no audit event
(b)(c) after resume the re-read row is not committed (or the file is gone and state gc_pending): not reported, 0 audit events; 200/200 iterations 0 false positives
(d) reported exactly once
```
**Max execution time**: 60 s; **Dependencies**: PostgreSQL

### IT-04-13: Master key startup, key check, rewrap
**Summary**: key errors are typed and stop startup; `init_key_check` refuses wrong keys; rewrap changes keys without touching files.
**Traces to**: AC-43, AC-65, AC-72
**Input data**: key file missing; 31 and 33 bytes; correct 32 bytes on empty volume (creates `.keycheck`); other key with `.keycheck` present; correct key with `.keycheck` deleted and blobs present; ring `1=k1,2=k2` with blobs wrapped by 1; `rewrap_batch(1,2,n=100)` over 450 blobs; interruption after batch 2.
**Expected result**:
```
FileMissing, WrongLength, (none), KeyCheckMismatch, KeyCheckAbsentButBlobsExist from load_and_verify with the operator text "data is unreadable without the master key"; empty install creates .keycheck only when blobs table and volume are both empty
init_key_check with a wrong key and >= 1 blob: KeyCheckSampleFailed{blob_id}, .keycheck NOT written; right key: written, audit admin_action; empty blobs table: sample skipped
rewrap: batches until 0 rows left; SHA-256 of every blob file identical before and after; reads work during and after; interrupted run resumes; new blobs use the current id; key 1 removable afterwards
```
**Max execution time**: 30 s; **Dependencies**: PostgreSQL

### IT-04-14: OrphanSweeper
**Summary**: files without a row older than `orphan_age` are orphans; partial scans delete nothing.

**Description**: `orphan_age = 500 ms`; 100 files with rows, 20 orphans older than age, 10 orphans younger, plus an unreadable prefix directory in a second run.

### IT-04-15: Missing blobs are typed findings
**Summary**: `BlobMissing` and `find_missing` instead of errors.
**Traces to**: AC-73
**Description**: 50 committed blobs, delete 7 files, 2 rows still `uploading` without file.
**Expected result**: `open`/`read_head` on the 7 -> `Err(BlobMissing)` (typed, not Io, not panic); `find_missing(batch = 20)` returns exactly the 7 ids over 2 calls (throttled stat), excludes `uploading`; `DoctorCheck` result for the volume lists the same ids; GC and scrub treat a missing file as a finding.

### IT-04-16: EpochMarker and health
**Summary**: the marker is read/written only through the port; health probe fields.
**Traces to**: AC-65
**Expected result**: `open_for_write(blob_id, wrapped_key, master_key_id, size)` continues a partly written blob after a dropped handle (read equals source; unknown `master_key_id` -> `KeyUnavailable`; deleted file -> `BlobMissing`). `read()` on a fresh volume -> absent; `write(7)` then `read()` -> 7; write is atomic (kill during write leaves old or new value, never partial); `BlobHealth::probe` -> `{writable, free_bytes, below_floor, unavailable_count}` with `unavailable_count == SELECT count(*) WHERE unavailable_at IS NOT NULL`; read-only root -> `writable = false`.
**Max execution time**: 5 s; **Dependencies**: PostgreSQL

### IT-04-18: 1 GiB read equals plaintext (single reader)
**Summary**: the reader used by downloads and the internal worker fetch returns the exact plaintext with bounded memory.
**Traces to**: AC-72
**Input data**: DS-25 (1 GiB dense), no range, consumed in 1 MiB reads.
**Expected result**: BLAKE3 of the stream == generator manifest hash; peak RSS growth <= 32 MiB (read-ahead 16 chunks x 64 KiB x lanes); there is no second decrypt path (crate exposes only `BlobReader::open`).
**Max execution time**: 30 s; **Dependencies**: PostgreSQL, DS-25. Env C-REF for the throughput part.

## Security Tests

### ST-04-1: Stolen disk
**Summary**: no plaintext on the volume without the master key.
**Traces to**: AC-43
**Attack vector**: read all files under `blobs/`, `.keycheck`, `.epoch`, free space of the loop image.
**Test procedure**:
1. Upload DS-09 style files with the marker and known strings (`PASSWORD=hunter2`).
2. `grep -a`/entropy scan the whole image and file tree; scan for the master key bytes.
**Expected behavior**: 0 marker hits, 0 known-string hits; master key bytes not present anywhere on the volume.
**Pass criteria**: 0 hits. **Fail criteria**: any.

### ST-04-2: Wrong or missing master key
**Summary**: bytes are never produced with the wrong key.
**Traces to**: AC-43, AC-72
**Attack vector**: start with another key; open blobs with a keyring lacking the id; rotate key and delete old.
**Test procedure**: `load_and_verify` with key B; `BlobReader::open` with wrapped_key of a blob wrapped under key A while only B is loaded.
**Expected behavior**: `KeyCheckMismatch` at startup; `KeyUnavailable`/`Corrupt` on open; no plaintext, no partial plaintext.
**Pass criteria**: 0 bytes returned. **Fail criteria**: any byte returned. System: FT-N-12, NFT-SEC-23.

### ST-04-3: Active ciphertext attacks
**Summary**: reordering, rollback, truncation and cross-blob splicing are detected.
**Traces to**: AC-7, AC-43
**Attack vector**: IT-04-4 cases plus restoring an older copy of a chunk (rollback), moving a whole file to another blob id, using blob B1's `wrapped_key` for B2's id.
**Test procedure**: apply each to a copy, call `open` and consume.
**Expected behavior**: `Corrupt` or `KeyUnavailable` every time (AAD = blob_id on chunks and on the wrap).
**Pass criteria**: 0 successful reads in 8+3 cases. **Fail criteria**: any. System: NFT-SEC-25.

### ST-04-4: Path traversal and id forgery
**Summary**: file paths come only from server-generated UUIDs.
**Attack vector**: `open_for_write`/`open`/`discard` with ids `../../etc/passwd`, `00/../..`, non-UUID, UUID with uppercase/braces.
**Test procedure**: construct ids from strings and call every port.
**Expected behavior**: id construction fails (typed) or lookups return `BlobMissing`; no filesystem access outside the root (strace-like decorator: all opened paths start with the blob root).
**Pass criteria**: 0 paths outside root. **Fail criteria**: any.
**Traces to**: AC-59

### ST-04-5: Cross-account blob access
**Summary**: a foreign blob id is `None`.
**Traces to**: AC-59
**Attack vector**: B calls `BlobCatalog::get_ref(B, A.blob_id)`; B submits A's `BlobRef` to `open` (the port trusts the caller, so the check lives in the catalog and in 03).
**Test procedure**: as listed; then `GcQueue::pending_for_account(B)` after A schedules.
**Expected behavior**: `None`; pending counts only own blobs.
**Pass criteria**: 0 foreign refs. **Fail criteria**: any.

### ST-04-6: RLS and role on `blobs`/`blob_gc`
**Summary**: runtime role sees only its account scope; no DDL.
**Traces to**: AC-59
**Attack vector**: raw select under B scope; GC/scrub run in system scope; `ALTER TABLE blobs`.
**Test procedure**: as listed.
**Expected behavior**: B sees only B blobs; sweepers see all; DDL denied (NFT-SEC-46).
**Pass criteria**: 0 foreign rows, DDL denied. **Fail criteria**: otherwise.

### ST-04-7: Key hygiene in logs, metrics and errors
**Summary**: no key bytes anywhere observable.
**Traces to**: AC-43
**Attack vector**: log/metric/error scraping; core-dump style leakage.
**Test procedure**: run all error paths (wrong key, tamper, missing); scrape logs, `/metrics` text, `Display`/`Debug` of every `BlobError`/`KeyError`; compile-time assertion that key types implement zeroize-on-drop.
**Expected behavior**: ids only; no hex of key bytes; `Debug` of key types prints a redaction.
**Pass criteria**: 0 matches of the 32 key bytes in hex/base64 across outputs. **Fail criteria**: any.

### ST-04-8: Block rewrite with different bytes (nonce reuse)
**Summary**: 04 must not seal two different plaintexts with one key and nonce.
**Traces to**: AC-43
**Attack vector**: caller calls `write_block(handle, i, bytes_A)` then `write_block(handle, i, bytes_B)`.
**Test procedure**: write block `i` with bytes A and wait for the token; (1) write block `i` again with the same bytes A: it succeeds and the file on disk is byte-identical to before; (2) write block `i` with bytes B (same length, different content): it fails with `BlockConflict` and the file on disk is still byte-identical to before; (3) read the blob: block `i` returns A; (4) repeat (2) with B differing in one bit, in the first byte and in the last byte of the block; (5) a concurrent pair of writers for index `i` with A and B: exactly one content wins and every read returns it; (6) after a simulated crash between the write and the ack (reopen with `open_for_write`) the same bytes A are accepted again.
**Expected behavior**: an identical second write is accepted and changes nothing; a different second write is refused with `BlockConflict` before any sealing or writing. **Pass criteria**: steps (1) to (6) give exactly the results above; the on-disk bytes of the block never change after its first successful write; no read ever returns two different plaintexts for one index. **Fail criteria**: two plaintexts at one offset readable as valid, a different second write accepted, an identical second write refused, or any byte of the file changed by a refused write.

## Test Data Management

**Required test data**:

| Data Set | Description | Source | Size |
|----------|-------------|--------|------|
| DS-09 | dense file with plaintext marker per MiB | generated (seed 20261103) | 5 GiB (1 GiB slice for component runs) |
| DS-25 | 1 GiB dense file | generated | 1 GiB |
| DS-33 | master keys 1 and 2 | generated per run | 64 bytes |
| Chunk-size corpus | sizes 0, 1, 65,535, 65,536, 65,537, 2 MiB, 5 MiB+7 | seeded generator | < 10 MiB |
| aead-stream vectors | oracle outputs for IT-04-2 | generated at build by the pinned crate | < 100 KB |

**Setup procedure**:
1. One `postgres:18@sha256:<pin>` per binary; migrate as `sunnycloud_migrator` into `tmpl`; per test `CREATE DATABASE ... TEMPLATE tmpl`; component runs as `sunnycloud`.
2. Per test blob root: temp directory (functional) or loop-mounted XFS image (IT-04-5, IT-04-7, perf), master key from DS-33, manual `Clock`, ms-scale retention/lease/age config.

**Teardown procedure**: drop the database; unmount and delete the image/dir; leak check: file count under the root equals committed + uploading rows.

**Data isolation strategy**: database and blob root per test; generated corpora read-only and shared; no test touches another test's volume; privileged loop-mount tests are tagged `needs-root` and SKIP with `NOT-RUN(C-priv)` when unavailable.

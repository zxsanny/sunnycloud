The JSON summary's line counts are almost twice the per-line ones. The likely cause: 08 has unit tests in `src/`, so the library is built twice, once for the unit-test binary and once for the integration binary. The summary counts each build's copy of a line, and the copy in the unit-test build is mostly unexercised. The 11 and 12 entries pass under the same gate, probably because their files are covered in both builds. This cause is not confirmed.

Within `accept_output` the per-line report leaves only these lines uncovered:
- the storage-error branch;
- line-count artifacts (parameter lines, braces).

The `SizeMismatch` branch (a body longer or shorter than its declared length) was uncovered too. It is now covered by `accept_refuse.rs` `a_body_longer_or_shorter_than_its_declared_length_is_refused_and_nothing_is_kept`.

## What is needed

The path gate cannot hold one function at 90%. It holds a file or a directory. Two choices:

1. Make `check-coverage.sh` gate on merged line coverage, for example from the lcov the coverage job already merges, instead of the JSON summary. Then add the three 08 entries. Check that the 11 and 12 entries still pass.
2. Or move `accept_output` and the claim statement into small files of their own, and gate those.

Option 1 is the simpler fix: the gate then measures what the report shows. It changes the gate's numbers for every entry, so run the whole coverage job once to see the new figures.

## Replay

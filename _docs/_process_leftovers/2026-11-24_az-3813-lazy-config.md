# AZ-3813 AC-5: `admin setup-token` and `key-check` need the whole server configuration

Found 2026-11-24 by the cross-command suite (`src/server/tests/cli_suite.rs`, module `lazy`). Two tests are written and `#[ignore]`d with this file's name; they fail today.

## What fails

IT-12-18 and AZ-3813 AC-5 say `migrate`, `admin setup-token`, `key-check` and `openapi` succeed with no sign-in provider and no worker token configured. The real binary does that for `migrate` and `openapi` only.

- `sunnycloud admin setup-token` with only `SUNNYCLOUD_DB_API_URL` and `PUBLIC_URL`: exit 3, `invalid configuration (7 problems): providers, share_grant_key, blob_root, worker_api_token, master_key_file ... required setting is missing`.
- `sunnycloud key-check` with the database URL, a 32-byte master key file and `BLOB_ROOT`: exit 3, `public_url, providers, share_grant_key, worker_api_token ... missing`.

## Cause

Every service builder of the composition root (`src/server/src/root/*.rs`: `Db`, the identity, key and blob services, the abuse limiter) asks the context for `ServeSettings`, which binds every key of the server table and runs every owner's start validation (`command_config.rs`: `ConfigCheck::Server`). Any operator command that builds one of those services therefore needs the full `serve` configuration. AZ-3790 left each command task to bind its own keys (`operator_command_surface.md`, "Configuration binding per command"); AZ-3794 and AZ-3797 did not, and `composition_root.rs` and `command_config.rs::only_serve_and_the_migrate_commands_ask_anything_of_configuration` pin the present behaviour.

## What is needed

A decision and a change, not a test edit: per-command settings for the commands that build services (at least `admin setup-token`, `admin create`, `admin reset`, `key-check`, `admin keycheck-init`), each binding only the keys its services read, with the owner validation of only those sections. `Settings` has required fields (`providers`, `worker_api_token`), so this touches `sc_config` as well as the root builders. Not done here: it is a refactor across about ten files and the design belongs to E-22 (owner of the composition root).

When it lands: remove the two `#[ignore]` lines in `cli_suite.rs`, change the two rows of `it12_coverage_map.md` from `known failure` to `pass`, and `lazy_context`/`command_config` tests that pin "unrestricted" move with it.

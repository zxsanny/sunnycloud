# Mode B assessment: clients (desktop, web, mobile) and media pipeline (raw, 2026-11-03)

Scope: attack on `solution_draft01.md` for the desktop daemon, Tauri settings window, Svelte web client, Flutter apps and the thumbnail/transcode workers. Prior work (`raw/media_pipeline.md`, `raw/sync_protocol.md`, `mve_desktop.md`, `mve_server_media.md`) is not repeated; this file lists what it missed or where it is too optimistic.
Tier key: L1 official/spec/vendor docs, L2 maintainer/bug tracker/own measurement, L3 blog/news, L4 forum/issue thread. "[limited source]" = single weak source, search-engine summary only, or my inference from training knowledge (not fetched). Sources marked (F) were fetched and read in full; the rest are search-result summaries only.
Own measurement (source 51) is the only new hard data: ffmpeg 8.0.1, AMD Ryzen 9 3900XT, `taskset -c 0-3` (4 distinct physical cores, SMT siblings are 0/12), RTX 3080, synthetic 10 s clips (testsrc2 + noise): 4K30 10-bit HEVC HLG at about 92 Mbit/s, and 1080p30 H.264 at about 29 Mbit/s. One CPU model and synthetic content, so absolute numbers are [limited source]; ratios are what matter.

| Test (10 s clip, 4 cores pinned) | Wall time | Speed vs real time |
|---|---|---|
| A: 1080p30 SDR H.264 to x264 veryfast CRF 23 | 3.0 s | 3.3x |
| B: 4K HLG HEVC to 1080p x264 veryfast, no tone mapping | 8.0 s | 1.25x (output tagged BT.2020 + arib-std-b67 in 8-bit yuv420p: wrong colours) |
| C: same with zscale + hable tonemap to BT.709 | 16.0 s | 0.63x (output correctly tagged bt709) |
| D: B with h264_nvenc p4 cq 23 (CPU decode and scale) | 7.8 s | 1.3x |
| E: C with h264_nvenc | 15.8 s | 0.63x |
| F: 1080p SDR to h264_nvenc | 2.1 s | 4.8x |
| G: 4K HLG, NVDEC + scale_cuda + NVENC, no tone mapping | 2.2 s | 4.5x (distro ffmpeg has no tonemap_cuda) |
Output size at nominal "quality 23": x264 CRF 23 gave 2.2 MB (B) and 3.1 MB (C); NVENC cq 23 gave 10.6 MB and 11.0 MB. Rate-control scales differ, so this is not a quality comparison [limited source].

## Contrarian views found

- Sync-as-backup is accepted by some product designs (this one explicitly), but backup vendors and incident reports (4, 5, 52) argue deletes and ransomware propagate; the counterweight here is that the guard (B1) and retention grace (AC-30) cost little and do not add a user-visible trash.
- "Use Electron for Linux consistency": sources comparing Tauri and Electron say WebKitGTK varies by distro and lags Chromium, so Electron removes a class of bugs (at 150 to 400 MB idle); not applicable to a 1% CPU / 100 MB daemon but relevant to the settings window choice (B23). Figures are blog-grade [limited source].
- Hardware encoders: some community tests rate NVENC at or above x264 medium at streaming bitrates, others (Chips and Cheese) find x264 slightly ahead on complex content (48). Nobody ran a controlled Ampere/Ada study; do not assume either way, measure in S5.
- Browsers can play HEVC now (49), which weakens the case for transcoding everything; the opposing view is that Firefox/Linux and older Chrome lack hardware decode, so compatibility copies still help (B18).
- Hash-wasm authors judge BLAKE3 SIMD not worth the bundle size (39), contrary to the assumption that WASM SIMD will make in-browser hashing cheap.

## Items confirmed OK

- NVENC session cap of 12 on all GeForce cards is correct per NVIDIA's matrix (41); the draft's "session limits on consumer GPUs" is accurate.
- Plain per-block `fetch(PUT)` of 2 MiB blocks matches what all browsers support; the draft's protocol needs no streaming request bodies on web (35).
- Hint-only watcher plus own settle and periodic rescans is the right shape (Syncthing relies on the same: watcher plus hourly scan, 3).
- iOS foreground plus system-scheduled upload, with no promise, matches Immich's own FAQ (26); D1 stands.
- `keep=none` thumbnails and Postgres-backed job lanes are sound; thumbnail/transcode job separation is a lesson Immich also reports.
- Slint as fallback is licence-compatible with the GPL decision (D3).
- Rejecting symlinks that leave the root is consistent with Syncthing (never follows symlinks, 2).

## Selected-decision changes proposed

1. Desktop settings UI: Slint primary, Tauri fallback (B23); S3 run on both. Owner may instead choose the localhost-browser option with the listed hardening.
2. NVENC: from "Selected + gate" to "opt-in, off by default, CPU is the acceptance baseline" (B19); AC-28 gets a 1.5x speed and equivalence condition.
3. Server: add blob GC grace period (B1, owner decision because of "no trash").
4. Mobile: single shared uploader (B12) before S9.
5. AC-7 and AC-9 wording per client (B9, B14).
